# Wii Flight Stick Project Status

## 1. プロジェクト概要
Wiiリモコン（RVL-CNT-01 / Motion Plus）の情報をPCで取得し、IMUデータ（加速度・ジャイロ）、ボタン状態、拡張機能を取得するとともに、LEDやモーターを操作できるGUIアプリケーションを開発する。

- **言語**: C# (.NET 9.0)
- **UIフレームワーク**: WinForms (Win32ネイティブに近い操作感)
- **通信ライブラリ**: Native HIDAPI (`hidapi.dll`) を使用したP/Invoke

## 2. 現在の進捗状況
- [x] デバイス接続の実装（VID: 0x057E, PID: 0x0330）
- [x] 基本的なボタン情報の取得とUIへの反映
- [x] LEDおよびモーター制御コマンドの基礎実装
- [x] IMUデータの生値取得（現在、モードやオフセットにより一部不正確な状態）
- [x] GUIのデバッグ特化型レイアウトへの変更

## 3. わかったこと (Findings)
### ハードウェア・プロトコル仕様
- **EEPROM保護ルール**: Output Reportを送信する際、最初のバイトのビット2 (0x04) をセットしないとEEPROMメモリを上書きしてしまうリスクがある。
- **データレポートモード**: 
    - Mode 0x30: 基本ボタンのみ。
    - Mode 0x31 / 0x35: 加速度センサーを含む。
    - ジャイロ（Motion Plus）の有効化には、特定の初期化シーケンスまたはパケットが必要。
- **IMUデータの構造**: `wii_motionplus_reader` のサンプルコードより、加速度とジャイロは特定のバイトオフセットに配置されていることが判明。

### ソフトウェア・実装状況
- **ボタンマッピング**: Byte 1 がボタン0-7、Byte 2 がボタン8-15に対応。
- **UI制約**: B5, B6, B13, B14 は非表示とする。

## 4. 実装案 (Implementation Plan)
### 短期目標（デバッグ・基盤強化）
1.  **安全なコマンド送信の実装**: `WiiRemoteHandler` 内で、すべてのOutput Reportに対して自動的にビット2 (0x04) を考慮する処理を組み込む。
2.  **IMU解析の精密化**: 拾ったC++サンプルコードのオフセットに基づき、`WiiPacketParser` の加速度・ジャイロ抽出ロジックを修正。
3.  **ジャイロ有効化ボタンの追加**: サンプルから特定した「ジャイロ有効化パケット」をワンクリックで送信できるボタンをGUIに追加。

### 中長期目標（機能拡張）
1.  **角度計算の実装**: 加速度とジャイロを組み合わせた補完フィルタ（Complementary Filter）を導入し、ピッチ・ロール・ヨーの算出を行う。
2.  **モーター制御の高度化**: 振動の強弱や持続時間を調整できるUIの実装。

## 5. 根拠 (Justification)
- **安全性**: EEPROM保護ルールはデバイスの故障を防ぐために最優先で遵守する。
- **正確性**: 計算（角度変換）を挟む前に、まずは「生の値」が正しく届いていることを確認することで、デバッグの難易度を下げる。
- **効率性**: カスタムパケット送信やモード変更ボタンをGUIに集約することで、Wiki等のドキュメントと照らし合わせながら迅速な試行錯誤を可能にする。
